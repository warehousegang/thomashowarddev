Fourth Down: from historical games to accountable NFL forecasts

An end-to-end, production-inspired predictive ML application: ingest real games, reconstruct pregame evidence, publish probabilities, and keep the record after kickoff.

Fourth Down estimates the probability that the designated home team wins an NFL regular-season game, conditional on a non-tied result. I built it to demonstrate the full engineering path around a predictive model: data provenance, time-aware features, reproducible evaluation, usable explanations, and a record that survives a wrong prediction.

The application runs a real trained model against current-season schedules. It also exposes historical analysis, forecast history, postgame scoring, and interactive research demonstrations. It is an Applied AI portfolio project with production-inspired controls. It does not establish commercial forecasting reliability or a betting advantage.

Separate model development from serving a forecast

Python owns data ingestion, feature construction, inference, evaluation, and artifact generation. React and TypeScript present the resulting static JSON. The browser validates the artifacts and the arithmetic behind a prediction; it does not train a model or ask an LLM to invent a probability.

This boundary keeps the public application inexpensive and inspectable. Source code, ML jobs, and tests stay in a separate repository. The portfolio receives a checksummed static build at /fourth-down/; its existing pages continue to use their original routes and assets.

Historical and current data serve different purposes

The historical pipeline uses a retained, hash-verified 2010–2023 nflverse schedule extract with Python, nflreadpy, and pandas. Training uses 2010–2022. The application preserves 2023 validation outputs and earlier chronological comparisons so a visitor can inspect measured results without rerunning training.

The current pipeline requests the season-specific schedule and completed results from SportsDataverse NFL NextGenStats data. It currently supports seasons from 2026 onward. Each raw capture records its source URL, retrieval time, and hash. The pipeline does not fetch an all-season table that would silently bring the protected 2024–2025 outcomes into current forecasting.

Public sports data can arrive late, change, or omit information. A passed kickoff time is not proof that a game finished. A usable result requires explicit final status, validated scores, and a known game date. Schedule changes and uncertain kickoff times are represented as states the interface can explain, rather than filled with invented timestamps.

Separate nflverse feeds provide injury reports, depth-chart context, and basic team statistics. These have their own provenance and freshness checks. They are context only: injuries, player news, weather, depth-chart position, and prior-season strength do not change the frozen model's probabilities. A missing injury report does not mean a healthy roster, and a depth-chart entry does not confirm a starter.

Reconstruct what could have been known before the game

For historical features, the cutoff is midnight in America/New_York on the game date. Only completed games on strictly earlier dates contribute. The current game's score, later games, and same-day outcomes cannot enter its team record. Historical source corrections remain a limitation: the retained extract does not prove the original publication time of every historical value.

Current-season inference adds an availability check. Its cutoff is the earlier of the decision time and game-date midnight Eastern. A prior final result must have been observed strictly before that cutoff. The provider does not supply a trusted completion timestamp, so the pipeline conservatively uses the first observed final result. It never treats kickoff plus an assumed game duration as proof of availability.

This can deliberately withhold a prediction. If the first saved capture arrives too late to establish pre-cutoff availability, an apparently complete record still lacks the evidence needed for inference. That is preferable to silently using information learned after the decision.

Team state resets each season. Week 1 uses neutral smoothing priors, not last year's strength. Bye weeks add no observations; rest comes from the last eligible completed game. Missing data and postponed or rescheduled matchups carry explicit warnings or exclusions. Tests exercise future-result contamination, cutoff boundaries, season resets, missing fields, and schedule changes.

Four features, one frozen probability calculation

The deployed incumbent is schedule-v1-741cf41752, an L2 logistic regression trained on 3,347 non-tied regular-season games from 2010–2022. Its StandardScaler was fitted on training data only. The exported raw-space coefficients already incorporate that scaling; serving does not fit a new scaler or apply the transformation twice.

Each input is the home team's value minus the away team's value, calculated from eligible games in the current season:

  • Smoothed win rate: (wins + 2) / (games + 4). A historical tie contributes half a win to team state.
  • Season scoring margin: the sum of points scored minus points allowed, divided by games + 4.
  • Recent scoring margin: the sum of margins in the last five games, divided by min(games, 5) + 2.
  • Rest: days since the last eligible completed game, capped at 14, with a seven-day default when no prior game exists.

The intercept plus the weighted feature differences gives a log-odds score. The logistic function converts it to the home-win probability; the away probability is its complement. A 0.5 threshold selects a winner. Factor explanations show contributions to this calculation, not causal claims about football.

The model has no player-level, injury, weather, betting-market, or prior-season-strength inputs. It also has no explicit neutral-site adjustment: the designated-home intercept remains in use for neutral and international games. These are material limitations, especially early in a season. The model is frozen; displaying a new matchup does not change its coefficients, preprocessing, features, or threshold.

Compare probabilities on the same eligible games

The benchmark is the training-only home-win frequency, about 55.72%, applied to every matchup. A 50/50 probability baseline and the original logistic regression provide additional references. All reported 2023 comparisons use the same 272 non-tied regular-season games. Ties are excluded from binary scoring, although earlier ties can contribute to feature history.

Accuracy measures winner selection. Brier score averages squared probability error; log loss penalizes confident mistakes more strongly. Lower is better for both probability scores. Calibration views include bin counts because a small group of games cannot support a strong claim that a probability is reliable.

The frozen model's mean Brier difference from the home-win baseline is −0.009918. A paired bootstrap with 2,000 week-block resamples gives a 95% interval of [−0.024715, 0.006382]. The interval includes zero. The point estimate is better, but this comparison does not establish a statistically secure improvement.

2023 was used for model selection, so these are validation results, not an untouched test or a promise of future accuracy. The 2024–2025 candidate evaluation remains locked. The holdout is partially exposed because legacy baseline aggregate results were previously observed; it is not described as pristine. No candidate holdout result is presented here.

The retained release snapshot has zero completed, scored prospective games. The application therefore shows an empty prospective scorecard instead of substituting historical accuracy. Historical comparisons, synthetic lifecycle tests, and simulations do not count as real upcoming-game performance.

Publish a forecast that can be inspected later

Each versioned forecast contains a stable matchup ID, teams, season and week, kickoff timestamp, data cutoff, generation timestamp, model version, all feature values, home and away probabilities, and source provenance. Content-addressed filenames and checksums connect what a visitor sees to the saved inputs.

The React application checks schemas, hashes, timestamps, and consistency with the model calculation before rendering probabilities. Current Week Forecasts is separate from retrospective 2023 Matchups. Visitors can inspect why the model favors a team, identify missing evidence, and distinguish source age from forecast generation time.

Freshness has consequences. Source age above 24 hours produces a warning, and data older than 48 hours cannot generate a new probability. The browser stops presenting an upcoming probability at kickoff or artifact expiry, whichever comes first. The expiry is bounded by source-update time plus 48 hours and generation time plus 24 hours. Reloading a page reloads published files; it does not refresh the upstream provider. Browser time checks also depend on the visitor's device clock.

Keep the forecast before evaluating the outcome

The archive retains every forecast version with a receipt combining the artifact hash and stable game ID. Identical payloads remain auditable but are deduplicated for scoring. Eligibility is reconstructed from the original observations, not a later corrected data capture.

For the headline prospective record, a deterministic policy selects the latest eligible prediction issued before confirmed kickoff, independently of the outcome. It is designated after kickoff and remains provisional until a verified final result arrives. A changed schedule fingerprint, including kickoff, requires a new eligible pregame forecast; the older record remains visible with its exclusion reason.

Outcome reconciliation requires explicit final status and verified scores observed after kickoff. It does not infer completion from the clock. Missing, canceled, postponed, tied, or ineligible games receive explicit treatment rather than fabricated binary scores. A result without a preissued eligible forecast is not backfilled into the prospective record.

The application can score retained versions separately, while the headline scorecard counts one selected prediction per game. Brier score, log loss, accuracy, calibration counts, and baselines use the same eligible population. Corrections produce a new operations artifact without rewriting the original forecast. Deterministic postgame analysis separates observed facts, forecast error, hypotheses, and missing evidence; an upset alone cannot establish what caused a model to be wrong.

Demonstrate research without overstating automation

Model Intelligence includes a seeded outcome simulation and a deterministic research walkthrough. The simulation draws binary outcomes from a saved probability with a repeatable seed. It illustrates variability conditional on that probability. It does not measure model accuracy, prove calibration, estimate parameter uncertainty, or simulate football scores.

The research walkthrough follows plan, inspect, hypothesize, and propose steps using cited saved inputs. It is implemented as deterministic application logic. It does not run an LLM, retrieve new research autonomously, execute an experiment, or alter a forecast.

A separate research-only challenger has saved chronological evaluations, calibration checks, ablations, and season-week uncertainty analysis. It has not replaced the frozen incumbent. Its remaining limitations include calibration failures in historical seasons, missing historical publication vintages, and the absence of a full prospective season. Prior-season-strength features for 2026 would also require protected 2025 information.

Improvement is controlled: a hypothesis can motivate an offline experiment, but a loss does not trigger automatic retraining or promotion. An LLM-assisted investigator is a future extension. It could retrieve cited evidence and propose experiments; any new predictive input, revised model, or holdout access would still require explicit evaluation and approval. Injury and news explanations cannot be used to manufacture a different probability.

Use a small deployment boundary, with a path to scale

The deployed shape is static React plus versioned JSON, served with the portfolio on GitHub Pages. A local refresh command prepares current evidence and forecasts. An inactive, SHA-pinned GitHub Actions workflow is prepared for manual artifact generation; recurring execution and automatic website publication are not enabled. A reviewed artifact import updates only the application's directory.

This design targets $0 additional recurring hosting cost with the existing public Pages site and public-repository runners, excluding the existing domain renewal. It needs no inference server, paid sports feed, or LLM service. Data attribution and dependency license notices travel with the application, which uses original text-based team identifiers.

Commercial scale would require more operational guarantees: permitted data with reliable publication timestamps and service expectations, durable object storage for observations, idempotent scheduled jobs, monitored freshness and reconciliation, and a model registry with controlled promotion. Higher traffic can still use cached static forecasts; individualized or low-latency inference would justify an API. Those are architectural extensions, not capabilities claimed for this portfolio deployment.

Local checks cover temporal feature integrity, frozen-model consistency, reproducibility, archive selection, result reconciliation, artifact safety, frontend contracts, accessibility, and desktop/mobile routes. They support confidence in the implementation. They cannot substitute for accumulating genuine prospective outcomes.

A transferable approach to predictive systems

My separate referral-completion modeling work uses synthetic healthcare data; Fourth Down uses historical and current sports records. Both depend on the same distinction: what is known now versus what was available when a prediction was made.

Fourth Down makes those decisions inspectable, from source observation to postgame record. Open the application to follow that path. The archived Forecast Lab prototype remains available as design history, with its hand-authored sample probabilities clearly labeled.
